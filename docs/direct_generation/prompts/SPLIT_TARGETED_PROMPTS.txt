SPLIT-TARGETED SPECIALIST PROMPTS — FOR REVIEW BEFORE THE RUN
=============================================================================================

Twenty-eight prompts: TWO VARIANTS of each arm — WITH the dev-derived few-shot anchor and
WITHOUT it — for the six paired instruction splits (one prompt each) and the four unpaired
high-stakes splits (one per label). The two variants differ by the anchor block ALONE, so the
pair measures how much of a targeted set's quality comes from the measured DESCRIPTION and
how much from seeing two real rows. Rendered by:

    .venv_claude/bin/python scripts/generate_split_targeted.py --dump-prompts <file>

Batch size is shown as 5 and the avoid-block as a placeholder; a real call carries up to 20
sampled openings. Nothing else differs from what will be sent.


WHAT CHANGED FROM THE `--kind` ARMS
-------------------------------------------------------------------------------------------
The `--kind` arms pinned the shared six-kind eval-data description to one kind. That text
names a split's SUBJECT MATTER and says nothing about its SHAPE, so those sets got the topic
right and the structure wrong. Following the hu_harm method on `human_harm_last`, each split
now has:

  1. a description written from MEASUREMENTS of the split file (row counts, pairing, role
     sequence, mean/median character lengths) rather than from recollection;
  2. a few-shot anchor taken from `dev_samples/`, NEVER `eval_sets/` — generated rows become
     training data and the probe is scored on eval, so anchoring on eval would copy test
     content into the training set;
  3. a generation MODE that matches the split: PAIRED (one opening, two final replies, two
     rows) where the split is paired, UNPAIRED where it is not;
  4. an enforced shape — turn count, presence of a system turn, and whether the row ends on
     the assistant or the user. A row that misses it is DROPPED, not repaired, and the log
     reports how many.

The register is described, never quoted. On `human_harm_last` the first refusal description
quoted real refusal strings; 17 of 200 eval negatives came back reproduced verbatim and that
cell fell 0.9832 -> 0.9403 once the quotes were removed — a third of the apparent margin was
memorisation.


THE SINGLE BIGGEST MISS THE MEASUREMENTS FOUND
-------------------------------------------------------------------------------------------
EVERY instruction split is a FULLY PAIRED corpus — the same user turn answered once each way:

    anthropic_harmless_refusal   100 of 100 distinct user turns carry both labels
    bbq_substitution             100 of 100
    hc_context_drift              97 of 97
    hc_contradiction             100 of 100
    mm_substitution               92 of 92
    oig_context_drift             97 of 97

All six `--kind` arms were generated UNPAIRED. Pairing is what forces the classifier onto the
assistant turn, since everything before it is identical between the two rows; without it the
probe can separate the classes on the opening alone. This is a concrete reason those
specialists lost to their generalist, and it is fixed here.

High-stakes is the opposite: 0 user turns carry both labels in any of its four splits, so
those stay unpaired.


STRUCTURAL CEILINGS — TWO HIGH-STAKES ARMS CANNOT BE FULLY FAITHFUL
-------------------------------------------------------------------------------------------
Measured role sequences, and what the probe's own tokenizer does with them:

  anthropic_hh_balanced   (system, user, assistant [, user, assistant]...)      tokenizes OK
  mt_balanced             (system, user)  — 604/604 rows, NO assistant turn     tokenizes OK
  mts_balanced            (system, assistant, user, assistant, user, ...)       RAISES
  toolace_balanced        (system, user, assistant) + some with `tool` roles    tokenizes OK

CEILING 1 — mts_balanced is ASSISTANT-FIRST, and gemma-3's chat template requires
user/assistant alternation after an optional leading system turn. 85 of its 86 eval rows are
UNTOKENIZABLE by the same path that processes training data; they only score at all because
their activations are fetched precomputed from Kaggle and never tokenized locally. A
faithful specialist for this split therefore could not be extracted, and the arm would die at
extraction rather than produce a number.

  What this arm will do instead: the same content (a clinical context paragraph in the system
  turn, many very short history-taking turns, ending on the patient) but USER-FIRST — the
  patient speaks first instead of the clinician. One deviation, deliberate and logged. Read
  that arm as "the closest extractable approximation", not as the split.

CEILING 2 — mt_balanced rows END ON A USER TURN and contain no assistant reply at all. That
shape is extractable, but the earlier generators forced every conversation to end on an
assistant turn, so the `--kind` mt arm could not produce it. The shape rule is now per split,
so this arm writes (system, user) exactly as the split does.

A third, milder one: toolace_balanced has 18 rows using the `tool` role. `convert_tool_to_
assistant` rewrites those before extraction anyway, so the arm writes system/user/assistant
and loses nothing.


ANCHORS USED (all from dev_samples/, verified disjoint from eval_sets/)
-------------------------------------------------------------------------------------------
Paired splits take a dev user turn that carries BOTH labels, so the anchor is itself a real
pair. Unpaired splits take one dev row per label. The prompt says explicitly that the anchor
is for register and shape only and its content must not be reused; the leak check after
generation verifies that (zero eval rows reproduced, and no eval assistant string reproduced
verbatim) before any fit runs.


FIT PROTOCOL (unchanged, so results stay comparable)
-------------------------------------------------------------------------------------------
deepseek-v4-pro; each arm fit on that generator's own 50-row base; n=540 with 8 seeded
class-balanced draws plus one full n=600 fit; every fit scored on ALL splits, appended to
scripts/instructions_gen90.csv and scripts/highstakes_gen90_dev500.csv. That is exactly the
protocol behind the `--kind` specialists, the mixed steered arm and the unsteered arm, so the
only thing that changes between those results and these is how the set was prepared.
